- **v60 commit E (written 11-06 12:39–13:0x, branch v60-consolidate on top of 6f49fa5; gate v60i pending): the head sketch for MTP drafts.** Design as built (so a re-read after a compaction has all of it; design notes `v60/HEAD_SKETCH_DESIGN.md`):
  - **The sketch (kern/tg2_planes.h, `g_q6_ksk` = 1011):** the Q6_K head's 6-bit code q (value d × sc × (q − 32)) keeps bits 5 and 4 as two 1-bit planes, with the stored int8 sub-block scales; read alone they give the code with its low four bits at the middle of their range — the v27 rule: q − 32 → 16c − 24.5 for the 2-bit code c — the same rule the Q4_TG2 / Q5_K planes use. **Not** a second lossy requantization of dequantized weights (the textbook form; rejected: it would lose the block scales). Row layout for k values = 10k/32 bytes (k = 2048: **640 B**): [k/32 sub-blocks × 8 B: word 2s = bit 5 of sub-block s's 32 codes (value l at bit l), word 2s+1 = bit 4] [k/16 scale bytes: the blocks' 16 int8 scales as stored, scale 2s + hf for values 16hf..16hf+15 of sub-block s]. The block's fp16 d stays in R3's `d6` array (reused, not copied). Sub-block numbering is the R3 kernel's own (`q6_sub`: ql bytes 64h + 32(p&1) + i at nibble p>>1, qh bytes 32h + i bits 2p, scales 192 + 8h + 2p + hf), so s = 8·block + 4h + p. Size for this model: 248,320 × 640 = **158.9 MB** DERIVED (the design note's 127 MB left out the 128 scale bytes per row; 2 planes alone would be 127 MB). Shared PG_HD helpers (host test and GPU run the same code): `q6k_sketch_row_bytes(k)`, `q6k_sketch_block(b208, planes16, sc16)`, `q6k_sketch_half2(hi, nx, u8, hf, xsum16)` = 32(2·D5 + D4) − 49·X (twice the integer sum of (16c − 24.5)x over one 16-value half; D = `plane_dot32` on the half's bits, X = the half's Σx from `plane_dot32(mask, u8)` once per token and sub-block), `q6k_sketch_sub(d, xs, sc0, sc1, t0, t1)` = d·xs·(sc0·t0 + sc1·t1)/2 — the R3 kernel's exact form `acc += d * xs * float(sc0(a0 − 32x0) + sc1(a1 − 32x1))` with the sketch's integers.
  - **The dot (gpu_ops.cu `k_head_sketch_dot`, `(256)` blocks, 8 rows per block = one warp per row, 31,040 blocks):** the token's activation bit planes (`act_bits32` of the `act_q8x32` int8 rounding — the same rounding the exact product uses) and the per-half Σx built once per block in shared memory (`u8[128][9]` padded against bank conflicts, `xh[128][2]`, `xs[128]`); lane l takes sub-blocks l, l+32 (one `uint2` of planes + 2 scale bytes each; a warp's loads are contiguous 256 B + 64 B); the 1-bit route (AND + popcount) per 16-value half so each stored scale stays its own; `half_float(d6)` (gpu_decode.h, exact, = `quant::fp16_to_fp32`); `warp_sum` → `y[r]`. k 256–4096 (nsub ≤ 128).
  - **Top-64 (`k_topk_select`, one block of 1024):** radix select on the float's order-preserving key (`(u & sign) ? ~u : u | sign`), 4 passes of 8 bits from the top with a shared 256-bin histogram of the candidates (`(key & mask) == prefix`), the digit holding the k-th largest chosen each pass → the exact k-th key and how many of its ties are needed; then the ids above the k-th key and as many at it as needed (shared atomics; the set is exact, its order is not; ties exactly at the 64th place pick non-deterministically — the re-score decides and verify never sees any of it). k ≤ 1024.
  - **The exact re-score = the head's own kernel:** `k_gather_q6k_rows` copies the 64 picked rows' 208-byte blocks (13 int4 each) + d6 into a fixed 64-row scratch in R3's layout; `Impl::head_top` is a hand-filled `DevW` (`v` = the head's view, `sw.w/d6` = the scratch, `n_out = kHeadSketchTop = 64`, `r3 = true`), run by `prod_r3({{&head_top, lg_top}}, xn, 1)` — the same `lane_part_n` kQ6K path, the same lane split (k/128 lanes per row), the same `act_q8x32` input, a direct plan built once and keyed on `&head_top` — so each row's float equals the full head's value for that row **bit for bit by construction** (test (4) checks it); `argmax_rows` over the 64 → `k_pick_id` maps the index back to the vocabulary id → `top_d_out`.
