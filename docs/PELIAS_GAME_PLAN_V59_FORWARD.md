### C2. The five kernel / engine fixes (the attachment's §… ; each its own commit, each A/B'd against C1)
Order chosen by expected ms per token (DERIVED from the v58 stamps) and by risk; GP5 bit-for-bit is the gate for 1, 3 (Q6_K part), 4 and 5; fix 2 and 3 (s_lut) are exactness-preserving by construction and the test suite's "one token = verify batches bit for bit" and "4/5 bits = stored" cases must stay green.

**Fix 1 — unshrunk cache slot sizing (gpu_engine.cpp L3014-3046 `slot_b`, L480 `nlr()`, L3016 "with the MTP row too").** Today (READ-SRC L3015-3022) `slot_b` = max over all `nlr()` rows of `exp_rows(v, ex).rb * ne[1]` summed over gate/up/down — `exp_rows` (L331) returns the file's **stored** row bytes, never `planed_bytes` — so `rc_eff` (L3034) and the reserve `need = slot_b * rc_eff * nlr()` (L3042) are computed with 2.58 MB slots (the largest stored expert, a Q6_K-down layer). The v51 size pools (L2123-2250) then repack each layer's `budget = cslot * rc_eff` by the experts' real (planed) sizes, which is why v54b/v54c MEASURED 48 / 61 slots per layer at 3 / 2 bits instead of 43 — but (i) the fixed-slot fallback (`pools_ok == false`, L2234-2237) still uses 2.58 MB slots, (ii) every layer gets the same `budget` (layers whose largest expert is 2.16 MB waste the difference), and (iii) the MTP row (il = n_layer; `M.hot` all zeros; its experts stored-type with int8 tables, `build_bank` L3693 with `planed=false` at L3682) takes a full per-layer `budget` of `cache_mem` (L2250: `c.base = cache_mem + il * budget`) out of the same reserve. Fix: `slot_b` from `planed_bytes(WL(il), ex)` when `o.plane_bits > 0` (trunk rows), per-layer budgets from each layer's own largest planed expert, and the MTP row sized separately (its own stored-size pool, or no slots: `M.hot` is zero so every MTP pick is a file read today — the author decides which). Prediction (ESTIMATE): the MTP row's budget (1/41 of the cache, ≈83 MB of 3.41 GB) plus the per-layer budgets give +2..+5 slots per trunk layer at 3 bits (48 → 50-53; the pools already follow the bits, so the gain is the two leaks, not a re-sizing), misses −3..−8 % (replay54: misses scale ~linearly with slots in this range), −0.1..−0.25 ms per token at 3 bits (fit 55-70 µs per miss, ~36 misses: BUILD_LOG L365). Gate: GP5 bit for bit (slot count does not change arithmetic); the engine's summary line prints slot bytes and count.
