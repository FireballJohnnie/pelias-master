# Pelias new methods tally

**Rule before every run (author, 2026-10-28, after the int8 format mismatch):** a test that stands in for our own code (a kernel, a file format, the engine) first reads that code's exact format (file and function named in the script) and makes the reference match it value for value, with a unit test, before any machine time is spent. A result measured in another format is labelled with that format and is not counted for our code.

Unconventional or newly derived methods that are **proven to work**. Entry rule: measured on real hardware or real weights, with the result resolved (95 % interval clears zero) or measured directly (kernel throughput). Ideas that tied, missed or are untested stay in docs/PELIAS_GAME_PLAN.md, not here.

Methods 1-3 and 7 are one idea (rotation per 32); urm (game plan) is the test that turns it into a result against Unsloth at the same size. Methods 8-13 and 15-17 are the author's bit-level line (zip scales, the 8th bit as a gate, T-decode, bit tags, the light bit rotated). Methods 14 and 18 are the author's miss map and H gate applied to tokens and to the KV cache. Methods 19-25 are the near-tie accuracy line of 2026-10-29/30: planes, grading by the original, and spending bits by use (usage-tiered experts, worst-error blocks, top-N picks, the int4 core). Method 26 is the reference arithmetic itself.

**Proven not to work (kept so they are not retried):** pure 7-bit values everywhere (urm_Q7 +0.001122 vs urm_Z, resolved worse); a heavy (range) 8th bit (collapses when not read); the H gate on top of 3-bit tags (about 6 % above the K-line at 3.785 bpw); lossless rANS coding of active weights (codes already at 3.87 of 4 bits: -3 %); rotating the token table (-0.9 %) or the routed experts (no gain, R2b); uniform planes as a size-for-size win (a higher base type beats a plane bit for bit: Q5_K +1.0 bpw 0.254x vs +1 plane 0.355x); fp32 inputs on stuck tokens (no gain); expert picks as the near-tie lever (the router is F32, the drift is in the weights); one usage ranking for every text (WikiText's top 64 cover 35.9 % of chat+code picks); the reference's own margin as the fragility flag (AUROC 0.63); kernel v3 (no gain); a plain two-stage E8 codebook (ties the K-quant line at 4 bits); empty activation bit planes with one scale per 32 (none occur); (not proven either way: a level search weighted by the importance matrix; urm_ZT's two bad chunks turned out to be one or two flipped tokens each, and urm_ZT2 vs urm_ZT does not resolve).
