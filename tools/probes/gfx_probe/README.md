# gfx_probe 0.2.1 (Pelias probes P-G0 and P-G0b)

Copyright (c) 2026 John Lipka and the Pelias contributors. Apache-2.0.

Measures the Pelias bus building blocks on **Direct3D 12** and **Vulkan**, each **without** (the usual way) and **with** (the Pelias way), on the same GPU in the same run. The results replace the CUDA-based numbers in the gaming rows of masterwork Section 21 (21.5, 21.6).

| Test | Without | With | CUDA result it checks |
|---|---|---|---|
| submit | record and submit every job | replay one pre-recorded list of the same jobs | launch replay 3.08x to 6.56x |
| sync | fence round trip per hand-off | doorbell: a resident shader answers a CPU-written flag; P-G0b runs it in every memory and read style below | 94.4 to 13.34 us (7.08x) |
| upload | staging/upload heap plus a copy command | CPU writes straight into VRAM through the BAR (Vulkan) or the GPU upload heap (D3D12) | pinned uploads 2.23x |
| overlap | copy, then compute | copy queue and compute queue at once | 1.77x to 1.96x |

**P-G0b (0.2.0):** the first run (2026-10-26 13:14) found that the doorbell with its flag in system RAM never saw the CPU's write on either API, while the flag in VRAM answered in 0.80 to 1.3 us. The sync test now tries each memory with each way of reading the flag, to find the cause:

| | Vulkan | Direct3D 12 |
|---|---|---|
| Memory | system RAM cached, system RAM uncached, VRAM through the BAR | system RAM write-back, system RAM write-combined, VRAM GPU upload heap |
| Read | plain (`coherent volatile` / `globallycoherent`), atomic add of 0, Vulkan memory model device-scope acquire + make-visible (if the driver supports it) | plain (`globallycoherent`), atomic add of 0 |

CPU writes to the flag now end with a full fence plus SFENCE, so write-combined mappings flush too.

**0.2.1:** a doorbell variant counts only if all its rounds complete (`"complete": true`). In 0.2.0 the summary line printed the median of a run that stopped after 1 round (Vulkan system RAM cached, 2026-10-26 13:29) as if it had worked; the JSON was right.

Every job in the submit test is the same in all variants: one barrier plus one tiny dispatch. The sync test compares the doorbell against the faster of the usual waits. The upload test copies from ordinary application memory, as a game streaming an asset would. The overlap test sizes the compute job to match the copy.

## What it needs

- Windows 10 or 11, x64, with a Vulkan 1.2 and Direct3D 12 GPU driver (the NVIDIA driver installs both).
- Visual Studio 2022 or later (or Build Tools) with the C++ workload and a Windows SDK. Nothing else: Vulkan is loaded from the driver at run time, and the Direct3D shaders are compiled at run time by Windows' own `d3dcompiler_47.dll`.
- The Direct3D 12 GPU upload heap needs Resizable BAR on, Windows 11 24H2 or later, and a driver that supports it. Without these the probe reports the reason and still runs everything else.

## Safety

- The doorbell shader polls memory while the CPU answers. Each round is capped at 300,000 polls, so a stalled CPU ends the shader well inside Windows' 2-second GPU timeout. The screen may stutter for a moment during that test.
- Close anything else using the GPU first (an LLM server, games, GPU monitors that sample fast), so the numbers are the probe's alone.
- It writes only to `results\`.

## Files

```
src/main.cpp          command line, JSON output
src/vk_probe.cpp      Vulkan half (P-G0b: doorbell variants)
src/d3d12_probe.cpp   Direct3D 12 half (HLSL shaders inside)
src/common.h          timing, statistics, JSON
src/probe.h           the two halves' entry points
src/shaders_spv.h     SPIR-V of shaders/*.comp (generated by tools/embed_spirv.py)
shaders/*.comp        Vulkan shaders (GLSL source; doorbell_atomic and doorbell_mm are the P-G0b variants)
third/                Vulkan-Headers (Khronos, Apache-2.0 or MIT) and DirectX-Headers (Microsoft, MIT): headers only, with their licences
results/              JSON results
```

## Build (x64 Native Tools Command Prompt for VS)

```
cd /d <folder holding gfx_probe>\gfx_probe
cl /nologo /std:c++20 /O2 /EHsc /W3 /I third\Vulkan-Headers\include /I third\DirectX-Headers\include src\main.cpp src\vk_probe.cpp src\d3d12_probe.cpp /Fe:gfx_probe.exe /link d3d12.lib dxgi.lib
```

## Run

```
gfx_probe.exe
```

Writes `results\gfx_probe_<UTC time>.json` and prints a summary with each "without vs with" ratio. Options: `--only vulkan`, `--only d3d12`, `--out FILE`, `--jobs N`, `--trials N`, `--rounds N`, `--max-polls N`, `--upload-mib N`, `--overlap-mib N`, `--vk-device N`, `--adapter N`.

## Checks done before release (2026-10-26; repeated for 0.2.0)

- All sources compile with g++ 13 and clang 18 for Linux, and with clang 18 against the mingw-w64 Windows headers plus DirectX-Headers (`-fsyntax-only`). MSVC builds on the target machine.
- The four HLSL shaders compile with glslang's HLSL front end; the five GLSL shaders compile with glslang to SPIR-V 1.5. The memory-model shader gets the VulkanMemoryModelDeviceScope capability added by `tools/embed_spirv.py` (this glslang build leaves it out).
- The Linux build runs and writes valid JSON. This sandbox has no GPU; 0.1.0 ran on the author's machine 2026-10-26 13:14 (`results/gfx_probe_20261026_171413Z.json`).

## Labels

Every number this probe writes is MEASURED on the machine that ran it. Ratios are DERIVED from those measurements.
